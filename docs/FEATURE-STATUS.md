# Feature and evidence status

Updated 4 November 2026. This is an active engineering build, not a claim of full product or production readiness. `implemented` means code exists; `automated-tested` is limited to the named checks; `installed-tested` means observed in a launched native bundle. Remaining acceptance is listed explicitly.

Latest completed automated checkpoint: 277 Swift tests (237 app, 15 store, 25 core) and 29 Python installer/signing tests passed, including rejection of invalid secondary marks even when the primary target is correct. The signed installed binary passed cursor/notch synthetic-controller regressions, actual AppModel failure-feedback/queued-observer native acceptance, and five live Codex/public-authored-image grounding/native final-render cases. The latter bypasses AppModel acceptance, capture/AX/focus preparation and notebook mutation; physical clicks, microphone/audio and the actual Codex hotkey workflow remain separate unverified paths.

Subsequent GUI screen-guidance diagnosis: the running canonical app denied Screen Recording preflight while an older Settings entry appeared enabled; TCC reported a code-requirement mismatch. Direct CLI-context capture succeeded but does not verify GUI permission. With explicit user approval, only OpenCompanion's Screen Recording row was removed through System Settings, the exact /Applications/OpenCompanion.app was re-added, and its new row is enabled. The user then reported Thinking and supplied a shortcut-only answer rather than a circle while Codex was visible. That is progress beyond the earlier failure, not accepted guidance. Other permission entries were not reset. The configured signing identity and capture guard are unchanged.

Current-frame grounding now retains bounded AX/OCR geometry and image dimensions, resolves exact frame-scoped candidate IDs with native geometry authority, and matches the user's functional goal to visible labels such as New task. OCR remains nonactionable; pixel grounding remains available. Empty AX titles fall through to descriptions/help, focused-window reads omit values and secure/hidden subtrees, and disabled ancestor state propagates. The five installed-bundle/live-provider authored cases cover icon-only compose with distractors/disabled duplicates, collapsed and freshly revealed navigation, generic notes, and image-only sidebar grounding. All passed with one target and no scene; native circles/labels were visually inspected. Complete single-case times were 4.31–9.62 seconds, not a reliability or latency guarantee. No actual desktop capture, AX query, user click, audio or AppModel admission was performed in those cases. See [grounding details](CURSOR-UI.md#current-frame-control-grounding). The reference static study informs the design but proves no private model route or exact runtime parity.

## Current release gates

DeveloperID identity/notarization/update signing, real microphone/audio routes, physical multi-display/fullscreen/permissions, installed browser pairing, held-out tutorials, long sessions, and cold/warm100+ trial latency remain required before a complete production release. A local render export proves local layer output, not measured displayed FPS. No exact HeyClicky parity is claimed.
